# 기존 문의·알림·분석 보존 검증

기존 프런트엔드와 API는 기준 HEAD `9e30d40`과 바이트 단위로 동일함을 확인했다. 폼 동작·API 응답·알림 내용·분석 태그를 개선하거나 변경하지 않았다. 이 문서는 내부 기록이며 공개 산출물에 포함하지 않는다.

## 보존 대상

- 홈과 `/landing`의 `home_contact`·`landing_contact` 요청은 이름, 이메일, 문의자 유형, 희망 목적, 문의 내용을 기존 `POST /.netlify/functions/contact`로 보낸다.
- `/overview`의 `overview_download` 요청은 소속명, 이름, 연락처, 부서명, 직급, 이메일, 방문 경로와 선택 문의 내용을 같은 API로 보낸다.
- `netlify/functions/contact.js`와 `_smtp-mailer.js`의 기존 필수값·이메일 검사, 허니팟, 메일 HTML 이스케이프, 수신자·Reply-To·접수 구분과 SMTP 전송 코드를 유지한다. 코드 보존과 해당 기능의 실행 검증은 구분한다.
- 소개서 요청의 서버 처리는 담당자에게 보내는 알림이며 자동 PDF 첨부 또는 요청자에게 별도 메일을 보내는 기능을 추가하지 않았다.
- `scripts/analytics.js`의 기존 GA4 ID·로더·이벤트, UTM·referrer·sessionStorage 처리를 유지했다. 새 `generate_lead` 발생 지점이나 성공 ID 응답을 추가하지 않았으며 기존 이벤트 발생 시점을 옮기지 않았다.
- 문의 개인정보 동의 UI, 분석 동의 정책과 보관 기준을 임의로 작성하거나 변경하지 않았다.

## 실제 실행한 검증

| 항목 | 확인한 방법과 결과 |
|---|---|
| 원본 일치 | 폼이 포함된 JS·HTML, 분석 JS, API·메일러를 기준 HEAD와 비교해 차이 없음 확인. 개발 서버는 내부 파일 차단만 별도 수정 |
| 문의 성공·실패 | 원본 페이지와 production preview에 같은 브라우저 HTTP 대역을 적용. 홈·landing·overview × 데스크톱·모바일의 6개 검사 통과 |
| 실패 화면 | 대역 오류 응답 뒤 입력값 유지, 버튼 재활성화, 실패 문구와 제출 상태가 원본과 같음 확인 |
| 성공 화면 | 대역 성공 응답 뒤 입력 초기화, 버튼 재활성화, 성공 문구·제출 상태와 요청 method·payload가 원본과 같음 확인 |
| 중복 제출 | 6/6 통과, 최종 브라우저 28/28(47.4초)에 포함. 처리 중 기존 disabled 버튼을 반복 클릭해도 요청 1개를 유지하고 원본·preview가 같음 확인 |
| 분석 정적·단위 검사 | `npm run ga4:check` 통과. 기존 로더·ID·유입 URL·UTM·referrer·세션·저장소 제한의 대역 검사가 Node 21개에 포함되어 통과 |
| API 자체 SMTP·입력 검증 단위 검사 | 이번 최종 범위에서는 실행하지 않음. 브라우저 HTTP 대역은 API 함수를 실행하지 않음 |
| 실제 운영 수신·분석 수집 | 미실행. 소유자의 별도 확인 대상 |

브라우저 성공·실패 검사에서는 실제 SMTP를 사용하지 않았으며 담당자 메일함 도착이나 서버 필수값·이메일·허니팟 검증을 실행한 것으로 해석할 수 없다. 외부 CDN·폰트·Spline·GA 요청도 대역 처리했다. 분석 단위 테스트가 임의 이벤트를 어댑터에 전달하는 것은 실제 폼에 새 전환 이벤트를 구현했다는 뜻이 아니다.

## 결과 해석과 남는 제한

중복 검사는 원래 제출 버튼의 disabled 상태와 요청 1개 유지를 확인한 범위다. 합성 submit 이벤트, 새로고침·다른 탭·직접 API 재전송과 서버 전체의 영속 멱등성을 보장하지 않는다. 6개 결과는 전체 브라우저 28개에 포함되며, 기존 동작 확인을 중복 방지 기능의 신규 구현으로 표현하지 않는다.

원래 JS가 사전 렌더링한 DOM을 다시 생성하므로 JS 초기화 이전 입력값이 재설정될 수 있다. 이번 브라우저 폼 검사는 초기화가 끝난 화면에서 수행했다. 초기화 중 입력 보존까지 확인한 것은 아니다.

실제 API 입력 검증·SMTP 오류 처리·전달·수신함 도착, 소개서 안내와 GA4 서버 수집·전환 설정은 미검증이다. 기존 개발 서버는 실제 자격 증명이 있으면 메일을 보낼 수 있으므로 운영 전송 확인에 임의로 사용하지 않는다.

## 롤백

폼·API·알림·분석의 원본 소스는 변경하지 않았다. SEO 빌드·배포 설정 롤백은 `completion-report.md`의 절차를 따른다. 새 성공 ID 또는 전환 이벤트와 API를 묶어 되돌리는 절차는 적용하지 않는다.
